# Keep Commons interop detached from Graft verification

Graft exposes accepted knowledge to Commons only through a detached Commons source materialized from one accepted boundary. Selected public tables are materialized atomically, including typed zero-row tables; failure to project any selected table aborts construction rather than returning a partial source. A live store is snapshotted at construction, later commits require a new source, and `graft_commons_data_source()` returns only a concrete Commons data source. Commons owns file measures, fallback query paths, and its trust labels, while Graft neither ingests executable R as governed records nor interprets Commons traces as Receipts or Verification. Commons remains an optional dependency. The adapter uses only its public API, CI tests an exact pinned upstream commit, and runtime compatibility checks fail clearly rather than guessing when the public contract is incompatible. Graft extends Commons's agent interaction with accepted definition history, exact boundaries, and receipts rather than requiring prompt obedience or taking ownership of the agent loop. This preserves temporal coherence and avoids competing measure and trust lifecycles.
