# Expose composite semantic evaluation

Graft replaces the singular measure-listing and measure-evaluation interface with `graft_definitions()` and `graft_calculate()`. The calculation interface mirrors Commons: `graft_calculate(source, metrics, dimensions = NULL, filters = NULL, where = NULL)` requires at least one metric and infers the public-table target from the requested metrics. All metrics must resolve to one target; ambiguous definition names may be qualified as `target::name`. Dimensions may name public scalar columns or derived definitions, filters name accepted filter definitions, and every input resolves within the inferred target.

`where` mirrors Commons exactly: each predicate contains a required string `column`, an `op` from `=`, `!=`, `<`, `<=`, `>`, and `>=`, and a required string `value`, with predicates combined by AND. Values remain strings at the public and tool boundary, then Graft parses and binds them according to the data-dict column type; invalid or ambiguous coercions fail rather than relying on DuckDB implicit casts. Complex logic belongs in a reviewed filter definition. Graft exposes `graft_definitions()` plus one calculation tool rather than generating a tool per public table. The bounded catalog supplies each definition's identity, revision, target, kind, expression, documentation, direct dependencies, and eligible public columns; tool arguments remain plain strings rather than changeable generated enums.

Results place dimensions and metrics in request order, return one row when ungrouped, and sort grouped rows deterministically by their dimensions. A grouped result that exceeds the hard row bound fails closed instead of truncating or accepting a misleading `limit`. Successful evaluations carry the canonical Receipt containing every explicitly selected and transitively referenced definition as an ID, revision ID, and kind, sorted by ID; raw columns and simple predicates remain calculation inputs rather than synthetic definitions. Failed evaluations return classed errors and no valid Receipt. Implementations may retain attempted boundary or definition metadata for diagnostics, but Verification never treats it as evidence. This makes the public interface and provenance contract describe the actual unit of governed work rather than preserving an independently agent-ready measure abstraction.
