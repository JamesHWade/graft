# Model governed calculations as composable definitions

Graft models reviewed calculations as accepted definitions classified as metrics, filters, or derived values rather than as independently agent-ready measures. Authors supply `name`, `target`, and `expr`, plus optional `label`, `description`, and `details`; Graft derives the definition ID, kind, and dependency closure during plan validation. The pair of `target` and `name` is the stable semantic identity: expression or documentation changes create a new revision, while renaming or retargeting creates a new definition. `expr` follows the pinned data-dict expression contract, not a Commons-owned language. Graft validates and executes that contract and exports it without reinterpretation; stored SQL and R are not definition languages. Definition names are unique within their public table and may not shadow columns. Definitions may reference other definitions on the same public table when the dependency graph is acyclic, and a semantic evaluation may combine multiple definitions and public non-sensitive scalar columns over one public table at one accepted boundary, while cross-table composition remains out of scope. Public tables include class projections and normalized relation projections.

Definitions declared by the data-dict contract seed accepted definition records with contract provenance. Subsequent discovery and evaluation read those immutable ledger revisions rather than rereading a mutable external dictionary. This matches how analysts use a semantic layer, preserves receipt-grade history, and avoids encoding false per-measure independence through parameter and dimension allowlists.
