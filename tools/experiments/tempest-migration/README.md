# Tempest checkpoint migration experiment (#64)

Run from the repository root after the shared [setup](../README.md#run):

```sh
export GRAFT_EXPERIMENT_HOME="/tmp/graft-experiment-dependencies"
export GRAFT_EXPERIMENT_OUTPUT="/tmp/graft-experiment-evidence"
Rscript tools/experiments/setup.R
Rscript tools/experiments/tempest-migration/run.R
```

The full `tools/experiments/run.R` suite also runs this experiment. Use a fresh
output directory for each run. Provisioning requires network access; execution
uses only the installed packages and synthetic local fixtures.

## What runs

1. Load the two completed-product promotion bundles shipped with pinned Tempest.
   Validate each bundle through `tempest_read_promotion_bundle()`, create a
   public promotion plan, commit it, and obtain a verified promotion receipt.
2. Reaccept the unchanged initial result without creating new record revisions.
   Preserve its complete evidence selection. Accept the correction and record
   the original claim's reviewed supersession.
3. Capture checkpoints through Tempest's shipped briefing recipe. Export the
   required native history, original bundles and manifests, receipts, snapshots,
   runtime and source schemas, exact report text, and materialized evidence.
4. Import each native revision into the existing manifest artifact driver. One
   retained root records the native-to-artifact identity map and depends on all
   imported revisions. Native IDs retain their original meanings.
5. Read the target in a fresh process whose library contains only jsonlite,
   digest, and rlang, plus base R packages. Graft and Tempest must be absent.
6. Exercise missing history, incorrect receipts, incomplete dependencies,
   altered content, unsupported operations, withdrawal, and a refused import
   retry into a nonempty target. Separately verify that the current public
   `tempest_knowledge()` rejects a portable view.
7. Reopen the source read-only in a fresh process and validate all three original
   receipt objects against their native snapshots and record revisions. Rebuild
   each report's selection from its receipt. Compare reports, evidence, and snapshots; compare the
   entire source directory digest before and after target work and rollback.

## Evidence and scope

`results.json` records the result and source pins; [observed.json](observed.json)
retains the checked local run. `handoff.json` identifies the
retained manifest target and its root selection. Native source data and the
imported target remain in the output directory for inspection. All are synthetic.
The importer reads JSON and bytes; the native rollback uses only the trusted RDS
checkpoints, receipts, and snapshots generated by this fixture and never accepts
user-supplied RDS.

The profile covers one pinned Tempest schema and store format, at most 40 native
history rows, and the shared artifact layer's 50-object/1 MiB bounds. It rejects
other schemas and deletion/tombstone operations explicitly. The accepted native
claim's `superseded` state and the target host's withdrawal are preserved.

Original promotion bundles and schema-file text are retained byte for byte.
Native POSIX timestamps are tagged with hexadecimal epoch values so JSON does
not truncate fractional seconds. Tempest assigns a new retrieval timestamp when
materializing a resource; comparisons retain its content, identity, and revision
metadata rather than treating that new read event as accepted evidence.

The fixture bundles contain accepted Source metadata, evidence excerpts, and
ProgramArtifact identities. They do not contain complete external web bodies or
executable program payloads. Their hashes do not recreate those missing bytes.

The target is a historical reader, not a writer for future accepted research or
a supported Tempest knowledge provider. Retaining a receipt preserves source
acceptance evidence; it does not create an acceptance event in a new store or
authenticate an untrusted export. A trusted host supplies the handoff digest.
Interrupted migration can leave an incomplete target; this prototype requires a
new empty target and does not implement production cleanup or recovery.
